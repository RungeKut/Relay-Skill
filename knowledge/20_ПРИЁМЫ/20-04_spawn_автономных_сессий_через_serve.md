# Автономный воркер через serve

## Механизм

`.relay/agents.json` в проекте:

```json
{"glm": {"cmd": ["node", "<путь>/resources/glm/zcode.cjs", "-p", "{prompt}", "--cwd", "{cwd}"],
         "env": {"ZCODE_DATA_BASE_DIR": "<каталог данных воркера>", "ZCODE_LOG_CONSOLE": "1"},
         "timeout": 14400}}
```

`python relay.py serve --agent glm --poll 2` — постоянный процесс-ждун: берёт
задание из инбокса, создаёт worktree, спавнит headless-сессию `-p`, пишет лог
`.relay/log/<агент>-<id>.log`, переносит задание в `done`; без отчёта —
автоматический `status: fail` с хвостом лога. Токенов не тратит.

## Ключевое: изоляция каталога данных

Приложение ZCode и CLI на одной машине пишут токены в один файл
`~/.zcode/v2/credentials.json`: каждый вход затирает чужой набор, и вторая
сторона требует вход заново (поэтому раньше `login` разлогинивал приложение).
Лечение: `ZCODE_DATA_BASE_DIR` на каталог вне домашнего — воркер получает свой
`credentials.json`, свой `provider_config.json` и свой идентификатор
устройства; сервер видит отдельное устройство (как второй компьютер), сессии
не конфликтуют.

Вход воркера — один раз, с той же переменной:
`set ZCODE_DATA_BASE_DIR=<каталог> && node ...zcode.cjs login zai`.
Браузер приложение открывает с обрезанной ссылкой (всё после `&` теряется) —
полную ссылку взять из вывода login и открыть вручную. Модель по умолчанию
login пишет в `provider_config.json` рядом с credentials; дешёвую Flash-модель
прописать там же руками (`defaultModelSelection.modelId`).

## Наблюдаемость

* без `console` — вывод воркера в `.relay/log/<агент>-<id>.log`; `ZCODE_LOG_CONSOLE=1`
  делает его подробным; смотреть: `tail -f` (Git Bash) или `Get-Content -Wait` (PowerShell).
* `"console": true` в agents.json (Windows) — отдельное консольное окно на каждое
  задание с живым выводом; окно закрывается по завершении, отчёт — в `result/`.

## Осторожно

* Ссылка авторизации одноразовая и живёт минуты: протухла — генерировать новую.
* `ZCODE_LOG_CONSOLE=1` до входа не нужен, но не мешает.
* Шаблон `go.md` всё ещё описывает исполнителя-чат с циклом `listen` (20-03);
  при serve чат-исполнителю не требуется — решение о переработке шаблона за владельцем.
