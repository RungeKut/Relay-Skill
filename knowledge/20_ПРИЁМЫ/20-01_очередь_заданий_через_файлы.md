# Очередь заданий через файлы

## Что происходит

Лид (одна ИИ) пишет бриф в `<проект>/.relay/inbox/<агент>/<id>.md`; шапка
(`id`, `to`, `base`, `worktree`, `files`, `done`) дописывается командой
`send`. Человек говорит исполнителю: «посмотри файл go.md, ты glm». `go.md`
в корне проекта создаёт `init` из `templates/go.md`; в нём весь порядок
работы исполнителя. Человек говорит фразу один раз: исполнитель запускает ждуна `listen` (процесс, блокирующийся до появления задания; не cron, токены в ожидании не тратятся), берёт задание, работает, пишет отчёт, `finish` и снова `listen`. Коды ждуна: 0 задание взято, 4 заданий нет за `--max` секунд (по умолчанию 540, перезапустить), 5 остановка командой `stop`.

## Устройство

* **Захват** — `os.replace` из `inbox/<агент>/` в `work/<агент>/`: операция
  атомарна, две ИИ одно задание не возьмут. Пусто — код 3.
* **Изоляция** — каждая задача в ветке `agent/<агент>/<id>` и worktree
  `.relay/wt/<агент>-<id>` от `base` (HEAD при отправке). `--shared` —
  без worktree (чтение, документы).
* **Параллельность** — несколько агентов, у каждого свой ящик; лид раздаёт
  непересекающиеся наборы файлов (`files` в шапке), слияние делает сам.
* **Отчёт** — `.relay/result/<id>.md`, ≤ 15 строк: `status: ok|fail`,
  `commits:`, `tests:`, `notes:`. `finish` без отчёта отказывает.
* **Ожидание лида** — `relay.py wait` запускается фоновой командой; её
  завершение будит сессию, опрос токенов не тратит.
* **Чистота репозитория** — `init` дописывает `.relay/` и `/go.md` в
  `.git/info/exclude`; ни правил протокола, ни `.gitignore` проект не
  получает. Корень определяется через `git rev-parse --git-common-dir`,
  поэтому команды работают и из worktree агента.

## Как правильно

Бриф: пути, критерий готовности, запреты; отчёт лид перепроверяет (коммиты,
числа тестов) — исполнитель может ошибиться. Исполнители не пушат и не
правят корневые файлы правил и файл состояния проекта. После слияния:
`git worktree remove <путь>` и `git branch -d agent/<агент>/<id>`.

## Как неправильно

Держать правила общения в репозитории проекта (засоряют историю, их видят
все); циклический опрос из сессии лида (жжёт токены); раздавать задачи с
общими файлами (конфликты слияния).

## История

сторожем с обеих сторон; заменён ящиками, потому что один файл не даёт
